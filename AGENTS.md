# FLYZRDS contributor instructions

Read README.md, docs/STATUS.md, and the relevant spec before changing code.
Implement one requested phase at a time; preserve unrelated behavior.

- Web: TypeScript, Vite, accessible HTML controls, Canvas 2D. Phone-first, minimum 44px touch targets, safe areas, reduced motion. Code-native art is temporary.
- Brain research: separate Python process and ignored research/ directory. Pin commits/data hashes; never commit brain datasets, neural checkpoints, credentials, precise routes, or camera media.
- Label demo, reduced-model, and live-neural modes accurately. No sentience claims or implied transfer of memories. Do not silently fall back to demo on backend failure.
- Care is forgiving: pause while absent. No catch-up hunger. XP and bond are game mechanics.
- Runtime messages and imports are untrusted: validate versions, finite bounds, model identity, sequence/ticks, and sizes.
- One tab owns the pet. Storage failure stops advancement. Preserve corrupt saves until explicit replacement; reset/restore require confirmation.
- `npm ci && npm run check` and `python -m unittest discover -s services/brain -p 'test_*.py'` are the required checks.
- Record actual evidence and unavailable checks in docs/STATUS.md. DOM tests are not visual or real-device tests.
- Do not merge with failed required checks, force-push, buy compute, deploy, or modify DNS/Shopify without task authorization.
- Upstream code/data licenses are separate. No project-wide license has been selected.
